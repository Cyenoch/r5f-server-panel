# 07 · 面板文本编辑光标 + 日志区时间线归并

- **Status**: `ready-for-human`（实现与真机面板验证已完成）
- **Blocked by**: 无
- **归属文件**: `src/text-field.ts`（新增）、`src/ui.ts`、`src/settings-edit.ts`、`src/keys.ts`、`src/tui.tsx`、`src/tap.ts`
- **契约**: `spec.md` §契约 3（面板不虚构能力）、`CONTEXT.md` §不变量 4（输出如实）

## 起因（服主报告）

1. **编辑文本时没法调插入位置**：例如设置页「附加参数」，小键盘/主键盘的 ←→ 完全没有反应，只能一路退格重打。
2. **日志区顺序反了**：点「启动服务器」之后，引擎的启动横幅跑到「▶ 启动服务器」这一行的**前面**去了，读起来像"先有日志、后有动作"。

## 根因（两条都定位到具体代码）

1. 文本输入根本没有插入点：`EditState.buffer` 是裸字符串，只支持"末尾追加 + 末尾退格"；`EditEvent` 不带 `left`/`right`，`KeyEvent.left/right` 只被公告表单的种类/颜色消费。所以按键**到了面板**但没有任何代码路径处理它 —— 不是终端没送键。

   实测（ink 解析层）：小键盘方向键的两种编码都认得 ——

   | 序列        | 来源                                       | ink `parseKeypress` |
   | ----------- | ------------------------------------------ | ------------------- |
   | `ESC [ D`   | 普通方向键 / 关掉 NumLock 的小键盘（常见） | `left`              |
   | `ESC O D`   | 应用光标模式（DECSET 1）下的小键盘         | `left`              |
   | `ESC [ 3 ~` | Delete                                     | `delete`            |

2. 日志区是**两段拼接**而非归并：`combined = [...snap.logLines, ...console_]` —— 引擎日志整段排在面板动作输出之前，与真实先后无关。而 `fast()` 每次重读整个尾部窗口、只在**行数变化**时才更新状态：日志一旦 ≥500 行，行数恒为 500，面板就再也不跟随了（顺手一起修）。

## Change

- **新增 `src/text-field.ts`**：一行文本 + 插入点的纯模型（`insertText` / `deleteBefore` / `deleteAtCaret` / `moveCaret` / `caretToEdge`）。插入点落在**码点**边界上，代理对（emoji 等）不会被 ←/→/退格劈成两半。
- **`src/ui.ts`**：`renderField(field, width)` —— 带插入点的一行渲染。长值按显示宽度开窗（CJK 按 2 格算），插入点始终可见；插入点后面还有字时留一半宽度给它，否则编辑行尾就看不见后面。
- **`src/settings-edit.ts`**：输入模式支持 `←` `→` `Home` `End` `退格` `Delete`；保存提交的是同一个 `TextField.text`（校验路径不变）。
- **`src/tui.tsx` + `src/keys.ts`**：
  - 设置输入框、控制台提示符、公告表单的**文字行**共用上面那套规则；
  - 公告表单的**种类/颜色**保持原来的 ←→ 换值（原来的快捷键不动）；
  - 底部提示与对话框提示同步补上新键位。
  - **连按/粘包修复**：终端的同一次读取里可能塞进多个按键（连按方向键、粘包），每个事件都在同一次渲染周期里被处理 —— 都从同一份旧状态出发的话，最后只有最后一个按键算数。`useInput` 改用 `uiRef` 同步镜像推进状态，让它们按顺序各自生效。
- **`src/tap.ts`**：新增 `readTailState`（尾部整窗 + 水位线）与 `readDelta`（水位线之后的新行）。水位线永远停在**整行**边界：没写完的末行留给下一次读，断掉的多字节字符不会被写进去，CRLF 的行尾 `\r` 不会漏进内容。`readTail` 改为它们的薄封装。
- **面板日志区**：每行在**读到它的那一刻**入账（`PaneLine.at`），引擎日志与面板动作输出按时间归并；动作结束时先收一次日志再写「✔/✘」结论行，引擎刚写下的回执才会落在结论**上面**。

## Acceptance

1. 文本编辑：`←`/`→` 移动插入点，`Home`/`End` 首尾，`退格`/`Delete` 删字，字符插在插入点处；设置、控制台、公告表单三处一致。
2. 小键盘方向键（`ESC O D` / `ESC [ D`）与主键盘方向键行为相同。
3. 日志区里，**动作之后**才被读到的引擎行必须排在动作行**之后**；动作之前读到的引擎行保持不变。
4. 日志超过 500 行后，面板仍然跟随最新日志（旧实现会冻结）。
5. 中文/emoji 不被劈开：←/→/退格都以整个码点为单位。

## 验证配方（已跑过）

- **纯函数**：`routeKey` 走真实按键路径 —— 打开「附加参数」编辑器 → ←×2 → 插字 → 退格 → `Delete` → `Home` → 行首插字 → 回车，保存载荷与光标位置逐步断言（一次性脚本，跑完删除）。
- **增量读**：尾部整窗/水位线、半行留到下一次、CRLF、多字节被字节切开后重组（无 `U+FFFD`）、文件截断返回 `null`、500 行饱和后新行不漏。
- **真机面板（PTY）**：
  - 控制台：输入 `status` → ←×3 → 插入 `X` → 屏幕显示 `控制台▸ statuX▎s`；回车执行。
  - 设置页：`DOWN`×11（一次连按）**一步到位**选中「附加参数」（修复前 11 次只走 1 格）；进入编辑器输入 `+spire_showdebuginfo 1` → ←×4 → 插 `9` → 显示 `+spire_showdebugin9▎fo 1`；Esc 取消后 `r5-server.json` 与测试前逐字节相同。
  - 公告表单：`n` → `a` → `↓` 到「文案」→ 输入 `abcd` → ←×2 → 插 `X` → 显示 `abc▎d`；Esc 退出，`chat_announcements.csv` 未被改动。
  - 日志顺序：合成日志分片（`logs/`，测试后删除）里在动作**之后**追加引擎行 → 屏幕上该行出现在「▶ 控制台：status / 没有正在运行的实例 / ✘ 退出码 2」**之后**；动作之前追加的行仍在动作之前。

## 注释

- 面板的"按键连发合批"是 ink/React 侧的既有效应；本次只把面板自己的状态推进改成同步镜像，没有动 ink。
- 日志区时间戳记的是"面板读到它"的时刻（轮询 600 ms），不是引擎写下它的时刻 —— 因此引擎行的先后以**面板看到的顺序**为准；这正好满足"动作之后才出现的日志不许插到动作前面"。
- 种类/颜色的 ←→ 换值保持不变（原有快捷键，README 与对话框提示都写着）。颜色仍可打字，只是插入点停在末尾。
